## 核心方法

**研究背景**：构建高性能GUI智能代理面临的挑战：通用性与性能的平衡、步骤级与轨迹级准确性的不匹配、部署复杂性。

**核心方法 - 四阶段训练管道**：

1. **中场训练（Mid-Training）**：
   - 100亿token语料库，涵盖30+数据集
   - 迭代数据精炼：高保真样本从69.7%提升至89.7%
   - 基于DaaS的真实设备数据生成

2. **离线强化学习（Offline-RL）**：
   - Grounding领域：引入拒绝能力（Refusal Capability）
   - Navigation领域：解耦奖励系统

3. **规模化在线强化学习（Online-RL）**：
   - 全轨迹展开优化长期任务完成率
   - 复合奖励函数：任务完成奖励 + 步骤长度衰减 + 无效动作惩罚
   - GRPO算法计算轨迹级优势

4. **模型合并（Model Merging）**：
   - 使用TIES-Merge策略融合三个领域模型
   - 统一移动端和网页端的动作空间

## 实验结果

**主要性能对比**：
| 基准 | UI-Venus-1.5-30B-A3B | 基线最佳 |
|------|---------------------|----------|
| VenusBench-GD | **75.0%** | - |
| ScreenSpot-Pro | **69.6%** | - |
| AndroidWorld | **77.6%** | 73.3% (MAI-UI-32B) |
| OSWorld-G-R | **76.4%** | - |
| WebVoyager | **76.0%** | - |

**消融实验**：
- Online-RL使2B模型在AndroidWorld上获得+14.5%提升
- Model Merge统一多域能力时，Grounding轻微下降1.4%，导航提升2.1%

**关键数据点**:
- 性能提升: VenusBench-Mobile提升6.1%绝对值
- 资源消耗: 8B模型超越前代72B模型
- 对比基准: 40+中文真实移动应用验证

## 关键贡献

1. **中场训练**：大规模领域知识注入
2. **Online-RL**：解决步骤-轨迹准确性不匹配
3. **Model Merging**：构建统一端到端代理
