# Nemotron-Terminal: Data Engineering for LLM Terminal Agents

## 基本信息
- arXiv ID: 2602.21193
- 作者: NVIDIA

## 核心方法

**研究背景**：终端智能体训练数据策略不透明且难以规模化。

**核心方法 - Terminal-Task-Gen**：

1. **双策略数据生成框架**：
   - 数据集适配：将现有数学、代码、SWE基准转换为终端格式
   - 合成任务生成：通过种子数据和技能分类法构建场景

2. **数据集适配**：
   - 数学提示：163K条Nemotron-Cascade数据
   - 代码提示：35K条OpenCodeReasoning数据
   - SWE提示：32K条SWE-Bench数据
   - 使用Terminus 2模板映射为终端指令

3. **合成任务生成**：
   - 基于种子生成：以科学计算问题转换为终端任务
   - 基于技能生成：构建9大领域技能分类法，组合生成新颖场景
   - 预构建9个领域Docker镜像，单遍任务生成

4. **数据工程策略**：
   - 无过滤策略：保留失败轨迹优于仅保留成功轨迹
   - 单阶段混合训练优于两阶段课程学习
   - 标准32K上下文窗口优于扩展至65K

## 实验结果

**Terminal-Bench 2.0性能**：
| 模型 | 参数量 | 准确率 | 对比 |
|------|--------|--------|------|
| Nemotron-Terminal-8B | 8B | 13.0% | 5倍提升 |
| Nemotron-Terminal-14B | 14B | 20.2% | - |
| Nemotron-Terminal-32B | 32B | 27.4% | 超越480B Qwen3-Coder |
| Qwen3-Coder | 480B | 23.9% | - |

**分类别提升**：
- 数据查询：0% → 60%
- 模型训练：0% → 50%
- 安全：2.5% → 27.5%

## 关键贡献

1. 提出Terminal-Task-Gen双策略数据生成框架
2. 系统验证过滤策略、课程学习、长上下文训练的影响
3. 证明高质量轨迹数据比单纯参数规模更关键
4. 开源模型检查点和数据集
